# 006 — Run

**Status:** Draft  
**Phase:** API Design  
**Owner:** Agni SDK

---

# Overview

`run()` is the primary execution API of Agni SDK.

It starts an Agent execution and coordinates the complete lifecycle:

- Preparing execution context.
- Sending requests to the Provider.
- Processing model responses.
- Executing tools.
- Applying guardrails.
- Managing memory.
- Handling termination.
- Returning the final result.

The `Agent` defines **what an agent is**.

The `run()` function defines **how an agent executes**.

---

# Core Principle

The Runtime is the brain of Agni SDK.

The public API should remain simple:

```ts
const result = await run(agent, 'What is the weather in Pune?');
```

Behind this simple API, the Runtime manages the complete agent loop.

---

# Responsibilities

`run()` is responsible for:

- Creating a Run instance.
- Initializing RunContext.
- Executing the agent loop.
- Calling providers.
- Handling tool calls.
- Applying guardrails.
- Updating memory.
- Managing execution limits.
- Producing RunResult.

---

# Non Responsibilities

`run()` should not:

- Define agent configuration.
- Implement provider APIs.
- Execute tool business logic.
- Store permanent state.
- Know provider-specific formats.

---

# Basic Usage

```ts
const result = await run(agent, 'Explain TypeScript');
```

Returns:

```ts
{
  success: true,
  output: "TypeScript is..."
}
```

# Public API

```ts
interface RunOptions<TContext = unknown> {
  /**
   * Request scoped data.
   */
  context?: TContext;

  /**
   * Maximum execution steps.
   */
  maxTurns?: number;

  /**
   * Abort execution.
   */
  signal?: AbortSignal;

  /**
   * Provider specific configuration.
   */
  providerOptions?: Record<string, unknown>;

  /**
   * Enable streaming.
   */
  stream?: boolean;
}
```

---

# Function Signature

```ts
function run<TContext>(
  agent: Agent<TContext>,
  input: string,
  options?: RunOptions<TContext>,
): Promise<RunResult>;
```

        |
       Yes

        ↓

# Multiple Tool Calls

The Runtime supports multiple execution cycles.

Example:

```
User

↓

Gemini

↓

Weather Tool (Pune)

↓

Gemini

↓

Database Tool

↓

Gemini

↓

Final Answer
```

The loop continues until:

- Model returns final response.
- Maximum turns reached.
- Guardrail blocks execution.
- Error occurs.
- User cancels execution.

---

# Error Handling Philosophy

Agni separates expected failures from exceptional failures.

## Expected failures

These are returned through `RunResult`.

Examples:

- Guardrail rejection.
- Max turns exceeded.
- Validation failure.
- Tool failure handled by policy.

Example:

```ts
{
  success:false,

  error:{
    type:"guardrail_blocked",
    message:"Request rejected"
  }
}
```

---

## Exceptional failures

These throw errors.

Examples:

- SDK bug.
- Invalid internal state.
- Unexpected programming error.

---

# Cancellation

Every run supports cancellation.

Example:

```ts
const controller = new AbortController();

run(agent, input, {
  signal: controller.signal,
});

controller.abort();
```

The Runtime passes cancellation signals to:

- Providers.
- Tools.
- Streaming operations.

---

# Turn Management

Agents can accidentally loop forever.

Example:

```
Model

↓

Tool

↓

Model

↓

Tool

↓

Model

...
```

The Runtime protects execution using limits.

Example:

```ts
maxTurns: 10;
```

When exceeded:

```ts
{
 success:false,
 error:{
   type:"max_turns_exceeded"
 }
}
```

---

# Streaming Mode

For long responses:

```ts
run(agent, input, {
  stream: true,
});
```

Returns execution events.

Example:

```
TOKEN

↓

TOOL_CALL

↓

TOOL_RESULT

↓

COMPLETED
```

Streaming is an extension of Runtime execution.

# Why Not Put run() Inside Agent?

Alternative:

```ts
agent.run(input);
```

Rejected.

Reason:

Agent represents configuration.

Execution is a separate concern.

Keeping them separate enables:

- Better testing.
- Multiple runtimes.
- Stateless agents.
- Easier composition.

---

# Why Not Make Runtime a Class?

Alternative:

```ts
new Runtime().run();
```

Rejected initially.

Reason:

Most users need a simple function.

Advanced configuration can be added later.

Example:

```ts
createRuntime({
  tracer,
  policies,
});
```

# Final API Example

Complete usage:

```ts
const agent = new Agent({
  name: 'Assistant',

  instructions: 'You are helpful.',

  model: gemini(),

  tools: [weatherTool],
});

const result = await run(agent, 'Weather in Pune?', {
  context: {
    userId: '123',
  },
});

if (result.success) {
  console.log(result.output);
}
```

---

# Final Decision

Agni SDK uses a functional `run()` API as the primary execution interface.

The Agent remains immutable configuration.

The Runtime owns execution.

The Provider communicates with models.

Tools perform actions.

Memory and Guardrails extend execution.

This separation creates a predictable, composable, and production-ready agent execution model.
