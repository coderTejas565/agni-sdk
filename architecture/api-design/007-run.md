# 007 — Run

**Status:** Draft  
**Phase:** API Design  
**Component:** Execution API  
**Owner:** Agni SDK

---

# Overview

`run()` is the primary execution entry point of Agni SDK.

It connects:

- Agent configuration.
- User input.
- Runtime execution.
- Provider communication.
- Tool execution.
- Context.
- Result handling.

The Agent defines **what the AI system is**.

The `run()` function performs **what the AI system does**.

---

# Design Decision

`run()` is an explicit execution function.

The SDK should not hide execution behind:

- Agent methods.
- Global state.
- Automatic execution.

---

```

+
```

Example:

```ts
const result = await run(
  agent,

);
```

---

# Full Usage

```ts
const result = await run(

  },
```

# Function Signature

Conceptual API:

```ts
async function run<TContext>(
  agent: Agent<TContext>,

  input: string,

  options?: RunOptions<TContext>,
): Promise<RunResult>;
```

---

# Parameters

---

# Agent

The configured AI system.

Example:

```ts
Agent<AppContext>;
```

contains:

- Model.
- Instructions.
- Tools.
- Guardrails.
- Memory.

---

# Input

The user's request.

Example:

```ts
'Book a flight to Mumbai';
```

---

Input represents:

```
User Intent

```

not:

- Application state.
- Authentication.
- Database connection.

Those belong in context.

---

# Run Options

Run options contain execution-specific data.

Example:

```ts
{
  (context, signal, maxTurns);
}
```

---

# RunContext

Context carries request-scoped information.

Example:

```ts
run(
  agent,

  input,

  {
    context: {
      userId: '123',
    },
  },
);
```

---

The same context reaches:

- Tools.
- Guardrails.
- Memory.

---

# AbortSignal

`run()` supports cancellation.

Example:

```ts
const controller = new AbortController();

run(
  agent,

  input,

  {
    signal: controller.signal,
  },
);
```

---

Cancel:

```ts
controller.abort();
```

---

Used for:

- User cancellation.
- Request timeout.
- Cleanup.

---

# Max Turns

Agent execution is iterative.

Example:

```
User

↓

Model

↓

Tool

↓

Model

↓

Tool

↓

Final Answer

```

---

`maxTurns` prevents infinite loops.

Example:

```ts
run(
  agent,

  input,

  {
    maxTurns: 10,
  },
);
```

---

Default:

```
Safe internal limit
```

# Result Handling

`run()` does not throw expected execution failures.

Instead:

```ts
RunResult;
```

is returned.

---

Success:

```ts
{
 success:true,

 output:"Sunny weather"
}
```

---

Failure:

```ts
{
 success:false,

 error:{
   type:"max_turns"
 }
}
```

---

# Why Result Instead Of Throwing

Some failures are normal execution outcomes.

Examples:

- Guardrail rejection.
- Max turns exceeded.
- Validation failure.
- Tool unavailable.

These are not programming errors.

---

Exceptions are reserved for:

- SDK bugs.
- Invalid internal state.
- Unexpected failures.

---

# Internal Runtime State

A run creates temporary state.

Example:

```ts
RunState{

 id,

 messages,

 context,

 currentTurn,

 status

}
```

---

This state exists only during execution.

---

# Run Isolation

Every call creates an independent execution.

Example:

```
Agent


run #1

context A


run #2

context B

```

---

No shared mutable state.

---

# Concurrency

Multiple runs can use the same Agent.

Example:

```ts
await Promise.all([run(agent, input1), run(agent, input2)]);
```

---

Because:

Agent:

immutable.

Run:

isolated.

# Final Decision

`run()` is the execution boundary of Agni SDK.

It connects static Agent configuration with dynamic execution.

The API intentionally keeps:

- Agent immutable.
- Context explicit.
- Results typed.
- Runtime hidden.

This creates a predictable foundation for tools, memory, guardrails, streaming, and future agent capabilities.
